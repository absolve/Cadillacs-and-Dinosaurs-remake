# 伤害、命中与复刻数据清单

> 本文是复刻取数的第二份核心文档：记录**命中/伤害结算链路、已提取的伤害表、状态→伤害映射**，
> 以及复刻还缺哪些数据、如何补。
> 数据来源：原版 ROM 字节（`E:\rea_dino\dino_main.bin`）+ Ghidra 12.1.4 反汇编 + 本文附录的提取脚本。
> 标注：**[ROMDATA]** 逐字节从 ROM 提取；**[静态]** 反汇编直接证据；**[推断]** 结构推理；**[待验证]** 需动态确认。

## 结论（TL;DR）

- **通用命中例程**有两个入口：`0x11EF0`、`0x124A6`；它们都从 **`0xA2EA4 + 攻击ID*8`** 取 8 字节记录，
  首字节就是**伤害**，其余是护甲削减、下一动作、硬直、效果和击退参数。**[静态]**
- **敌人攻击表 `0xA2EA4`** 共 **117 条有效记录**，伤害范围 **5 ~ 100**（0x64 可能是即死/特殊）。**[ROMDATA]**
- **玩家命中例程** `0x12526` 使用 **4 角色各自的攻击表**：
  `0xA26FC` 是 4 个 long 指针（P0~P3），分别指向 `0xA270C / 0xA28EC / 0xA2ADC / 0xA2CBC`；
  每角色 **120 条 × 4 字节**（伤害 / 护甲 / 下一动作 / 硬直）。**[ROMDATA]**
- **力量缩放**在 `0x2B904`：读取 `0xA320C + 攻击ID*2` 的 16 位倍率，`伤害 = 基础伤害 × 倍率 >> 5`；
  还叠加 `0xA32FA`（按状态）、攻击者 `+0xC6`、`0x5EE` 表等倍率。**[静态/部分推断]**
- **状态 → 伤害映射**：12 张主动作表中 **55 个状态**会在 handler 里写 `A6+0x58`（攻击 ID），
  已映射到 `0xA2EA4` 的伤害值（见 §5）。Hogg / Slice / Slisaur 的攻击 ID 在子状态或共用例程里设置，
  主表未覆盖，仍需补。**[静态]**
- **判定盒已闭环（静态）**：命中检查 `0x128F8` → 4 个碰撞例程；盒子 = 12 字节（Z/X/Y 三轴）；
  动画帧记录（10/12 字节两种）含受击盒与攻击盒索引。已批量导出
  **185 个动画集 / 2700 条动画 / 98771 帧**的逐帧像素盒（§8.5）。
  剩余：招式→动画 ID 映射、敌人动画集归属、每帧停留帧数（§8.6）。
- **玩家基础动画集是跨角色共用的槽位表**（§8.7，看图 + 结构推断）：
  Jack `set000` / Mustapha `set006` / Hannah `set012` / Mess `set018` **都是 32 段**，
  段号的 `loop/terminated` 标志几乎逐格一致、11 格帧数四人完全相同
  → **一套 `act_map` 服务四个角色**，换角色只换动画集与帧数表。
  工程侧已按此接线：`scene/actor/player/player.tscn`（通用）+ `jack.tscn` / `hannah.tscn`。
- **动画播放机制已闭环（§8.8）**：动画 ID = 传给 `0x120E/0x13A0` 系列的 `D0`，
  且 `D0` **就是素材包里的 `actNN` 段号**（同一张 word 偏移表的下标）；
  玩家用组表 `0x163E`（24 项 = 6 组 × 4 角色，与素材包分组互相印证）按 `A6+0x03` 选集；
  `A6+0x2F` 是「当前帧停留帧数」倒计时 → §8.6 第 3 项（帧时长）关闭。
- **玩家主动作表 = `0x190C4`（§8.9）**，子表在每个 handler 内（act `0x02` → `0x19FC0`）；
  40 处动画组调用已按主动作归位（两级分派：主动作表 → handler 内子表）。
  **组的语义以看图为准**：组0 = 基础（含拳帧）、组1 = 站 / 走朝向变体（全是长循环）、
  组2 = 抓取 / 投技、组3 = 少量短拳与举手姿态、组5 = 单帧姿态库。
  顺带定出**输入字节布局**：`A6+0xA0` = 当前输入、`A6+0xA8` = 新按下沿，
  低 4 位方向编码、bit4 / bit5 = 攻击 / 跳跃（`0x63AA` 用两者组合判「背向」派生）。
  **敌人动画集归属也已定位到写入点（§8.10）**：每张敌人表只有一个「生成态」写 `A6+0x40`，
  全 ROM 208 处写入、150 处命中已知集、118 处归到具体状态（Vice→set76/77/80/84-87 等）。
  仍缺的只是「动作字节 ↔ 招式名」与「分支键 ↔ 刷怪记录 OI」这两层语义标注。
- **复刻还缺**：武器伤害、弹幕参数、刷怪波次、输入窗口、宝物分值（详见 §6）。

## 1. 命中 / 伤害流程

### 1.1 通用命中（敌人攻击、通用受击）

入口：`0x11EF0`（单次）与 `0x124A6`（碰撞列表循环调用）。核心步骤：

```
A4 = 0xA2EA4 + attacker->0x58 * 8
 target->0x6E = target->0x6C          ; 保存旧 HP
 dmg = A4[0]
 target->0x6C -= dmg                   ; 扣血，<=0 时钳到 0（特殊目标钳到 1）
 target->0x78 -= A4[1]                 ; 护甲/防御值削减，下溢清 0
 target->0x7B = A4[2]
 target->0x06 = A4[2]                  ; 下一动作
 target->0x59 = A4[3]                  ; 硬直帧
 if (A4[4] != 0) effect(A4[4])         ; 0x962A 音效/特效
 D5 = A4[6]                            ; 击退参数
 target->0x9A = A4[7]
 knockback(D5)                         ; 0x12720
 target->0x24 ^= 1                     ; 面向攻击者
```

记录字段（8 字节）：

| 偏移 | 含义 | 说明 |
| --- | --- | --- |
| +0 | **伤害** | 直接扣 HP |
| +1 | 护甲削减 | 扣目标 `+0x78` |
| +2 | 下一动作 | 写入目标 `+0x06/+0x7B` |
| +3 | 硬直 | 写入目标 `+0x59`（帧） |
| +4 | 效果 ID | 非 0 调 `0x962A` |
| +5 | 保留/未知 | 当前未见使用 |
| +6 | 击退参数 | 传给 `0x12720`（D5） |
| +7 | 受击特效 | 写入目标 `+0x9A` |

### 1.2 玩家命中

入口：`0x12526`。目标从 `A6+0x70` 取，攻击表按**角色索引** `A6+0x20` 选择：

```
A4 = pointer_table[0xA26FC + (A6+0x20)*4]   ; P0~P3
A4 += (A6->0x58) * 4
dmg = A4[0]
call 0x2B904                                 ; 力量/状态倍率修正 D1
target->0x6C -= dmg
target->0x78 -= A4[1]
target->0x06 = A4[2]
target->0x59 = A4[3]
```

角色顺序（按人物选择写入值 0~3）：**P0 Jack、P1 Hannah、P2 Mustapha、P3 Mess**（**[高置信]**，见 doc/04 的作弊地址）。

### 1.3 HP 初始化与访问点（扫描结果）

| 地址 | 作用 |
| --- | --- |
| `0x4DC2` / `0x4DE8` | `move.w #0x64,(0x6C,A6/A0)`：HP = 100 |
| `0x5B066` | HP = 0x14（20） |
| `0x6AA34` | HP = 0x0A（10） |
| `0x5B90E` | `move.w D0,(0x6C,A6)`：由 D0 设置 HP |
| `0x18EC6` | HP→`+0x6E`，`subq.w #1`，清零：可破坏物 / 1 点伤害 |
| `0x3262A` | HP 比较、保存到 `+0x6E`、死亡分支（Hogg 等调用） |
| `0x32032` / `0x58CD6` | 读取玩家 HP `(0x32E0,A5)` |
| `0x11EF0` / `0x124A6` | 命中扣血（敌人表 `0xA2EA4`） |
| `0x12526` | 命中扣血（玩家角色表） |

> 完整 72 条 `A6+0x6C` / `A5+0x32E0` 访问点见 `E:
ea_ai_work\hp_refs.tsv`；
> 其他基址（A0~A4）上的 `+0x6C` 访问见 `E:

### 1.4 判定盒（机制已解出）

- 命中前置检查：`0x128F8`，按攻击者 `A2+0x4A` 与目标 `A3+0x4A` 的组合查 4 项 word 表 `0x1290E`，
  分派到 `0x12916 / 0x129A8 / 0x12A5C / 0x12B0E` 四个例程（区别在攻/守类别与朝向）。
- 每个对象的盒子表指针在 `A6+0x44`；当前帧的盒子索引在 `A6+0x48`（word）：
  - `+0x48` 高字节 = 受击盒索引（hurtbox）
  - `+0x49` 低字节 = 攻击盒索引（hitbox）
- 动画帧推进函数 `0x121E` 会从帧数据读一个 word 写入 `+0x48`，即**每帧盒索引来自动画帧数据**。
- 盒子记录固定 **12 字节 / 6 个有符号 word**：

| 偏移 | 字段 |
| --- | --- |
| +0 | Z 偏移 |
| +2 | Z 尺寸 |
| +4 | X 偏移 |
| +6 | X 宽度 |
| +8 | Y 偏移 |
| +10 | Y 高度 |

- 三轴判定（以 `0x12916` 为例）：先比 Z 区间，再比 X（`A6+0x24` 朝向为左时 X 取 `-offset-width`），
  最后比 Y 区间；三轴都相交才算命中。
- 玩家盒子表：`0x100000 + group*0x300`（每组 64 条），组号来自动画表 `0xB7472 + animID*8`
  的 `+6` word；负组走 `0x106000 + (-group)*0x200`（格式待核）。
- **已导出**：玩家 8 组共 **317 条非零盒子**（§8.1）、187 条动画→组映射（§8.2）。
  逐帧的盒索引需要动态采集，探针见 §8.3（静态动画脚本格式尚未完全解码）。

## 4. 力量 / 倍率与最终伤害

- 倍率表 `0xA320C`：16 位有符号/无符号值，按攻击 ID 索引；当前解析到的非零项：
  `0x03=48, 0x06=48, 0x0C=64, 0x10=64, 0x14=48, 0x1F=48, 0x2C=48, 0x2E=33, 0x34=48`。
- 基础公式（`0x2B904` 已验证的首段）：

```
最终伤害 = 基础伤害 × 倍率(0xA320C[攻击ID]) >> 5
```

  即倍率 32 = ×1.0、48 = ×1.5、64 = ×2.0。
- 之后还会叠加：`0xA32FA`（按目标 `+0x84` 状态的两组 [攻击ID, 倍率]）、攻击者 `+0xC6`、
  `0x5EE` 表（按目标 `+0x84*8 + A5+0x5EE`）。这一段尚未逐项验证，复刻时可先实现首段公式，
  再用 doc/07 的连击伤害（Jack 68 等）校准。
- 已知校验点：Jack 连击总伤害 **68**（力量 32）⇒ 基础 34 × 倍率 64 >> 5 = 68，与表结构一致。

### 8.4 动画脚本与逐帧盒

- 动画引擎有三个变体（都从 `A6+0x40` 指向的动画表取偏移）：

| 入口 | 帧记录 | 说明 |
| --- | --- | --- |
| `0x120E` / `0x121E` / `0x1380` | **10 字节** | 无 +10 扩展字 |
| `0x1420` / `0x1426` | **12 字节** | 多一个写入 `A6+0x60` 的扩展字 |
| `0x15E4` | **10 字节（无盒）** | 只更新 pose，不写 `A6+0x48` |

- 帧记录字段（10/12 字节通用部分）：

| 偏移 | 字段 |
| --- | --- |
| +0 | word D0：精灵描述符偏移（`0x11D220 + D0` → 写入 `A6+0x4C`） |
| +2 | word D1：备用索引（非负时覆盖 D0） |
| +4 | long D2：低 7 位 = pose；**低字节 bit7 = 分支标志** |
| +8 | word 盒索引：**高字节 = 受击盒（hurt）**，**低字节 = 攻击盒（attack）** |
| +10 | 12 字节版才有：扩展字（写入 `A6+0x60`，常见为精灵偏移递增） |

- 序列推进：`next = cur + size + (分支 ? word(cur + size) : 0)`；
  序列没有显式结束符（待机就是同一帧自循环），提取时用“记录内容重复 / 地址重复”判停。
- `0xB7472` 是**动画集表**：`[long 动画表][word ?][word 盒子组]`；
  动画表内是 word 偏移（长度 = 首个偏移 / 2，允许不同动画复用同一序列）。
  之前把它叫“脚本指针”不准确，已更正。

#### 8.8.1 引擎字段（修正 doc/09 的字段表）

| 字段 | 含义 | 证据 |
| --- | --- | --- |
| `A6+0x25` bit0 | 动画冻结（置位时不推进帧） | `0x1262: btst.b #0x0,(0x25,A6)` |
| `A6+0x28` | **当前帧游标**（指向帧记录，不是集表） | `0x1226/0x1236: movea.l (0x28,A6),A0` |
| `A6+0x2C` | pose（帧记录 D2 的低 7 位） | `0x1248: move.l D2,(0x2c,A6)` |
| `A6+0x2F` | **当前帧剩余停留帧数倒计时**，减到 0 才换帧 | `0x121E: subq.b #0x1,(0x2f,A6)` |
| `A6+0x40` | 动画集表指针（word 偏移表基址） | `0x120E: movea.l (0x40,A6),A0` |
| `A6+0x48` | 本帧盒索引（高字节受击盒 / 低字节攻击盒） | `0x1240: move.w (A0)+,(0x48,A6)` |
| `A6+0x4C` | 精灵描述符（`0x11D220 + D0*4` 取出） | `0x126C-0x1276` |

**帧时长（§8.6 第 3 项）就此关闭**：帧记录里没有时长字段是对的，
停留帧数由 `A6+0x2F` 这个运行时倒计时承担（handler 里能看到 `move.b #0x1,(0x2f,A6)` 这类显式写入），
所以「每帧停留几帧」要按状态读代码，而不是读表。

#### 8.8.2 引擎入口

| 入口 | 作用 |
| --- | --- |
| `0x120E` | 用 `A6+0x40` 的集表播放第 `D0` 段 |
| `0x121E` / `0x1380` | 推进 / 回退一帧（10 字节帧记录） |
| `0x1420` / `0x1426` | 同上，12 字节帧记录版（多一个写入 `A6+0x60` 的扩展字） |

「按对象 ID 选集」的实现（代码密度技巧，五个入口只差用哪个寄存器当基址）：

```

moveq #0,D1
move.b (0x3,A6),D1        ; D1 = 对象 ID（玩家 = 4×动画组 + 角色）

add.w  D1,D1              ; ×4

add.w  D0,D0
move.w (0,A0,D0),D0       ; ★ D0 = 段号 = 素材包里的 actNN
adda.w D0,A0
```

### 8.9 玩家主动作表 `0x190C4`（本轮闭合）

分派代码在 `0x190B6`：

```
moveq  #0,D0
move.b (0x6,A6),D0            ; D0 = 主动作字节
move.w (0x190C4,PC,D0),D1     ; 查表：handler = 0x190C4 + D1
jmp    (0x190C4,PC,D1)
```

- 表 `0x190C4` 共 24 项（动作字节 `0x00..0x2E`，步进 2），**12 项指向真实代码**，
  其余（`0x00/08/0A/0E/12/18/26/2A` 等）落在表区内 = 未使用值。
- **子动作分派在每个 handler 内部**，形状与主动作分派相同，例如 act `0x02` 的 handler
  `0x19FA8` 开头就是 `move.b (0x7,A6),D0 / move.w (0x19FC0,PC,D0),D1 / jmp (0x19FC0,PC,D1)`

### 8.10 敌人 / Boss 的动画集归属（§8.6 第 2 项：定位到写入点）
