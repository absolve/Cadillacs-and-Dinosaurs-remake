# 敌人与 Boss AI 逆向（M68k 静态 + FBNeo 动态验证）

> 本文基于原始 ROM 的静态逆向结果与 FBNeo debug 动态验证，供复刻工程实现 AI 时对照。
> 复现步骤、数据字典与已知坑见**附录 H**；逐状态命名见**附录 G**。
> 标注约定：**[已确认]** 有 ROM 字节/反编译直接证据；**[高置信]** 由多个结构证据交叉支持；
> **[推断]** 依据代码区域与结构推理，尚未动态验证；**[未知]** 尚未定位或无法确认。

## 结论（TL;DR）

- 原版敌人/Boss AI 是**两级状态机**：对象子类型（`A6+0x05`）先从**函数指针表**选出更新例程；
  更新例程每帧按**动作字节（`A6+0x06`，偶数）**查**动作表**调用状态处理函数；部分状态再用
  `A6+0x07` 查**子动作表**分派。**[已确认]**
- 动作表编码固定：`handler = 表基址 + signext16(表基址 + 动作字节)`，表项为有符号 16 位偏移。**[已确认]**
- 已解码 **12 张主动作表**（杂兵 1 张、Boss 类 11 张）、**9 张杂兵子动作表**、**7 张更新器指针表**，
  并反编译了 **154 个主动作处理函数 + 24 个可用子状态处理函数**（路径见附录 C）。
- **逐状态命名**：12 张主动作表共 **225 个状态**已给出功能级命名
  （待机 / 移动 / 冲刺 / 攻击 anim / 投掷 / 受击 / 起身 / 择招 / 转场），见**附录 G**；
  具体美术招式名与判定/伤害仍待补（§7）。
- 已生成 **344 条批量标注**（函数重命名 + 数据标签 + 注释），
  一键标注脚本与 CSV 见附录 E。
- **动态确认（2026-10-31，FBNeo Lua exec hook，手动通关验证）**：
  Vice `0x428D8`（OID 0x0048）、Butcher `0x5882E`（OID 0x00F4）、
  Slice `0x4C038`（OID 0x0064）、Morgan `0x51890`（OID 0x0090）、
  Morgue `0x53FDA/0x557F4/0x55816`（OID 0x00A0）、
  Tyrog `0x36C34/0x38CC6/0x38D0E`（OID 0x0010）、
  Slisaur `0x5C924`（OID 0x011C）、Fessenden 1st/多头 `0x67ED2/0x6965C/0x6967E`
  （OID 0x0178）、Tyrog 2 `0x6565A`（OID 0x016C）。
- **动态确认（2026-10-31，第 3 关 `stage` 字节 = 2，Stage Select 作弊跳关）**：
  Hogg 对象 `A6+0x03=0x26`、OID `0x007C`、HP `0x012C`（300）。
  常驻更新器 **`0x4FE9E`**（`sub=0`，本轮每帧命中，动作表 `0x4FEDE`）；
  切换更新器 **`0x5034C`**（`sub=2`，动作表 `0x5039A`，本轮仅短暂命中 3 次）。
  类分派入口 `0x4FE86`、指针表 `0x4FE8E`：
  `sub=0→0x4FE9E`、`sub=2→0x5034C`、`sub=4→0x5075E`（首字节 `rts`，空更新器）、
  `sub=6→0x2B35A`（共享存根）。`0x51890` 是 Morgan，与 Hogg 无关。
- **Boss 生成模板（cdree）中 `AI/SI = 00`**：Boss 的 AI 类不是由记录的 AI/SI 字节选择，
  而由对象 ID / 生成描述符决定；该描述符表尚未静态定位，归属最终需动态断点验证（附录 F）。
- **动作表存在复制体**：`0x4C06A ≡ 0x5C956`（Jaccard 1.00，Slice / Slisaur）、
  `0x36CA0 ≈ 0x656C6`（0.72，Tyrog / Tyrog 2）、`0x54066 ≈ 0x67F5E`（0.89，Morgue / Fessenden 模板）。
- 已提取的关键行为参数：Tyrog 拍击 **32.8125%**（`rand&0x3F <= 0x14`）+ 目标范围 **±6 px / ±82 px**；
  敌方无敌/眩晕窗口 **60 帧**；Boss 倒地**无**无敌帧；难度 HP 加成 `0/32/66/100/0/66/132/200`；
  目标选择接近均分（社区补丁值为 33.12% / 32.33% / 34.55%）。
- 字符串扫描对本 ROM **无效**：程序 ROM 无 ASCII，文本是图块。AI 定位全靠代码结构与 RAM 引用。**[已确认]**

## 2. AI 运行框架（已确认）

### 2.1 对象更新流程

1. 每帧 vblank IRQ（`0x542`）更新滚动/计时器，并调用若干子系统；
2. 对象更新器按 `A6+0x05` 子类型从**函数指针表**取出更新例程并跳转；
3. 更新例程统一做：无敌计时（`+0x79/+0x78`）→ 硬直/延迟（`+0x59/+0x7A`）
   → **动作分派（`+0x06`）** → 若干通用回调 → 把对象压入绘制链表；
4. 绘制链表：指针 `A5+0x6726`（后向压栈），数量 `A5+0x671E`，用于按 Y 排序绘制。

更新例程的共享骨架（以 `FUN_00053FDA` 为例，反编译见
`E:\rea_dino\ai\00053fda_FUN_00053fda.c`）：

```c
if (*(A6+0x79) != 0) { if (--*(A6+0x79) == 0) *(A6+0x78) = 0x0B; }  /* 无敌计时恢复 */
FUN_00012cb4();
if (*(A6+0x59) == 0) {                        /* 未被硬直锁定 */
  if (*(A6+0x7A) == 0) {                      /* 延迟结束 */
    func_0x00032d0c();
    if (*(A6+0xa1) == 0) FUN_00032b68();
    (*(code *)(TABLE + *(short *)(TABLE + *(byte *)(A6+6))))();  /* 动作分派 */
    func_0x000541f2(); func_0x0005426e(); func_0x000542b0(); func_0x000542d2(); func_0x000540fa();
  } else --*(A6+0x7a);
} else { --*(A6+0x59); *(A6+0x2f) = 1; }       /* 硬直/受击锁 */
FUN_00032f56(); FUN_000049ca();
/* 压入绘制链表 */
```

### 2.3 动作分派（`A6+0x06` → 动作表）

汇编形态（以 `FUN_00053FDA` 为例，重排后）：

```
MOVEQ   #0,D0
MOVE.B  (6,A6),D0          ; D0 = 动作字节（偶数）
MOVE.W  (d16,PC,D0.W),D1   ; D1 = 表项（有符号 16 位偏移）
JSR     (d8,PC,D1.W)       ; 目标 = 表基址 + D1
```

因此动作字节与状态一一对应：`动作字节 = 2 × 状态索引`，处理函数地址见附录 A。

### 2.5 生成流程与对象字段（补充）

刷怪记录为 16 字节：`TS(2) B1(1) ?(1) OI(2) PX(2) PY(2) AI(1) SI(1) DL(2) DI(1) IL(1)`。
生成入口 `FUN_0000FDAE`（`0xFE30` 附近）读取记录并把字段写入对象：

| 记录字段 | 写入对象字段 | 说明 |
| --- | --- | --- |
| `OI`（+4） | `+0x20` | 对象 ID 副本 |
| `PX`（+6） | `+0x08` | X |
| `PY`（+8） | `+0x10` | Y |
| `AI/SI`（+10/+11） | `+0x26`（word，低字节 AI、高字节 SI） | 姿态 / 子类型 |
| `DL`（+12） | `+0x5C` | 恐龙追踪上限 |
| `DI`（+14） | `+0x5B` | 掉落 ID |
| `IL`（+15） | `+0x96` | 智能/攻击性 |

对象类型由 `B1 & 7` 选择 4 项生成指针表 `0xFD46`：
`type0=0x483C`（敌人槽）、`type1=0x4860`、`type3=0x4818`（物件/木桶槽）。

**重要发现**：cdree 的 Boss 生成模板（`BossTypeByteMap.js`）中，8 个 Boss 的
`AI/SI` 均为 `00`——Boss 的 AI 类并非由记录的 AI/SI 决定，而来自对象 ID 对应的
生成描述符（该描述符表尚未定位）。因此 §4 的归属修正仍以“状态机同构/区域”为依据，
最终结论需用附录 F 的动态断点确认。

## 3. 通用敌人 AI

### 3.1 主动作表 `0x2A620`（15 状态）

状态 → 处理函数见附录 A。处理函数内部再用 `A6+0x07` 查子表，关系如下（均已在 ROM 中校验）：

| 主状态（`+0x06`） | 子表（`JMP (d8,PC,Dn)` 指令地址） | 子状态数 | 说明 |
| --- | --- | --- | --- |
| `0x00 / 0x02 / 0x04` | `0x2A6D6` | 5 | 待机/站立/受击类共用 |
| `0x06` | `0x2A860` | 5 | 与 `0x2A6D6` 共享部分处理函数 |
| `0x08` | `0x2A9D6` | 5 | |
| `0x0A / 0x0C` | `0x2AC10` | 6 | |
| `0x0E / 0x10 / 0x12` | `0x2ADE8` 与 `0x2AEBC` | 12 / 12 | 同一处理函数按条件选两张表 |
| `0x14 / 0x16 / 0x18` | `0x2AEBC` | 12 | |
| `0x1A` | `0x2AFFA` | 2 | |
| `0x1C` | `0x2B2F0` 与 `0x2B362` | 8 / 13 | |

子状态同样以偶数存储：处理函数里常见 `*(A6+0x07) += 2` 的推进写法。

**子表处理函数语义（已确认示例）**：

- `0x2A6E2`（`0x2A6D6[0]`）：按朝向 `+0x24` 设置/镜像动画偏移 `+0x14..+0x1C`，
  并根据 HP（`+0x6C`）切换受伤/正常动画组；
- `0x2A7F6`（`0x2A6D6[2]`）：调用 `0x4B58`、`0x189C`（落地高度）、`0x2A980`，
  随机调用 `0x121E`，HP 为 0 时置 `+0x80 = 1`，最后 `+0x07 += 2` 进入下一子状态；
- `0x2A86C`（`0x2A860[0]`）与 `0x2A6E2` 同构，说明两张表是同一“动画/位移框架”的不同参数集；
- 子状态 4/5（如 `0x316DA`、`0x31864`、`0x2EC08`）位于其他区域，按敌人 ID/类型分流。

> 其余子状态的语义（攻击前摇、判定、收招的具体分工）尚未逐个命名，
> 可在 Ghidra 中用附录 E 的标注后按 `+0x07` 值逐一跟踪。

## 5. 行为机制细节（从反编译提取）

### 5.1 追踪移动（示例：`0x35DAE` / `0x58E04`）

移动类状态统一按“目标位置 → 速度向量”工作：

- 追击坐标：`+0x88`（目标 X）、`+0x8A`（目标 Y）；
- 速度字段：多数敌人类使用 `+0xB0/+0xB4`，`0x588E0`（Butcher）与 `0x54066` 的部分状态
  使用 `+0xC0/+0xC4`；均为 16.16 定点；
- 例 `0x35DAE`（表 `0x35B24`）：每 4 帧比较 `+0x88/+0x8A` 与自身 `+0x08/+0x10`，
  写入 `±0x12000 / ±0x10000` 的速度，`+0xAE` 计时，`+0xA2` 子计时；
- 例 `0x58E04`（表 `0x588E0`，Butcher）：写入 `±0x18000 / ±0x10000` 的速度；
  冲刺标志 `+0xBA` 置位时把计时改为 `0x3C` 并把动作切到 `+0x06 = 0x18`。

**[已确认]**（汇编级）

### 5.2 随机决策与动作选择

- 随机数入口：`FUN_0000119C`；Tyrog 拍击用 `rand & 0x3F <= 0x14`（**32.8125%**）。
- 含随机分支的状态（汇编判定）：Tyrog `A2E/A3A/A3C`、Morgan/Morgue `A30`、
  Morgan `A26/A2A` 等，通常用于在多个动作转场之间随机挑选。
- `0x35DAE` 的尾段还存在“**32 项权重表 + 二级跳转表**”的选择结构
  （`0x72754/0x72854` → `0x36876`），推测用于移动/攻击子行为选择；
  该结构在其他类中可能复用，尚未逐类确认。

### 5.3 目标选择与距离

- Tyrog 拍击：竖向 `±6 px`、横向 `±82 px`，概率 `32/96 = 33.3%` 的有效采样中
  实际为 `21/64 = 32.8125%`。
- Slisaur 离屏：摄像机 `A5+0x744`，屏宽 384，左右容差 30 px（`0x1BC` 阈值）。
- 目标指针 `+0x76` 存 `0x8000+offset`，实际地址 = `A5 + (值 - 0x8000)`。

### 5.4 无敌、硬直与眩晕

- 无敌/眩晕计时：`+0x79` 递减到 0 → `+0x78 = 0x0B`；`+0x00` 标志 1/4。
- 敌人倒地后 **60 帧**眩晕免疫；Boss 倒地**无**无敌帧（Slisaur 刻意除外）。
- 受击锁：`+0x59 != 0` 时每帧递减并置 `+0x2F = 1`，期间不执行动作分派。
- 动作延迟：`+0x7A` 非 0 时只递减，不进入动作分派。

### 5.5 HP 与难度

- 玩家结构体 HP 在 `+0x6C`（`$FFB2E0` 附近），1 格 = 100 HP。
- 敌人 HP 初始化 `0x31436/0x31E34`，加成表
  `0/32/66/100/0/66/132/200`（难度 0~7），Boss 另有独立 HP 表（`0x6070E`）。
- 投掷型杂兵 HP=12（`0x5AAEE`）；副 Boss 200，最高难度 500/600。
- **完整伤害表、命中字段与状态→伤害映射见 [doc/10](./10-damage-and-hit-data.md)**；
  本文只负责 AI 状态机，伤害结算链路以 doc/10 为准。

对全部状态处理函数做了汇编特征分类（WAIT / MOVE_AI / TIMED_ACTION / RANDOM_DECIDE /
ACTION_TRANSITION / DOWN / GETUP），各表分布如下（逐状态功能命名见**附录 G**）：

### H.5 数据字典

- `semantics_by_state_asm.txt`：`== table 0xTABLE (n) ==` 开头，每行
  `A<hex> -> 0xHANDLER  CLASS  [FLAGS]`；`FLAGS` 由反汇编特征生成

  `FACING`、`HP`、`SET_LONG(...)` 等）。
- `state_features.tsv`：见 H.4；`calls` 是从 handler 提取的 `jsr/bsr` 目标（已去前导 0）。
- `actions.tsv`：`base`、`actionByte`、`entry`（表项有符号偏移）、`handler`；仅作参考，不完整。
- `asm_actions/*.asm`：文件名是 handler 地址的 5 位十六进制。

### H.6 已知坑清单
