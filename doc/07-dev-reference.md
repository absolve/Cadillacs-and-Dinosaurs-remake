# 复刻实现参考

## 结论（TL;DR）

- **大部分核心数值已有 ROM 实值，直接采用**（角色 HP 100、连击伤害 Jack 68 / Hannah 67 / Mustapha 65 / Mess 78、必杀伤害 20/20/20/23）；只有动作帧数、移速 / 跳高 / 攻击距离、敌人伤害、输入窗口、宝物分值还需实测。
- **四个最容易漏的机制**：力量每次被击中重掷（**残血越容易出高值** 36/42/48，最高难度可到 64；伤害 × 力量/32，最高翻倍）；敌人倒地 60 帧眩晕免疫；Boss 倒地无无敌（设计选择）；必杀是两段伤害（10 + 4）。
- **Godot 要点**：Y 排序基准取脚底；Hitbox + 自增 `hit_id` 防同一次挥击重复结算；数值全部 `Resource` 化；掉落表 32 分母直接取模；换色用调色板 `ShaderMaterial`。
- **玩家跑不出地图 = 四层夹取**：摄像机被关卡尺寸夹取 → 玩家 X 夹在视野矩形内 → Y 夹在该区域的**可行走带**（第 1 关 A 147/100、B 79/16、C 63/16）→ `lock` 段锁屏时视野右缘即是墙。建议每个区域一个 `AreaData` 资源 + 统一的 `clamp_to_area()`，玩家与敌人共用（见 [05 §边界](./05-stages.md#玩家为什么跑不出地图边界与锁屏机制)）。
- **计时**：原版 59.6 Hz 全帧计时，直接用 Godot 60 Hz 物理帧，1 帧 = 1 物理帧。
- **实现顺序**：先 Jack 单人跑通移动 / 连击 / 受击 / 倒地，**尽早加力量系统**，多人、Boss、全局流程放最后。

> 本页给出**复刻时的数值取舍与实现要点**。
>
> 好消息：**大部分核心数值已经从 ROM 中提取出来了**
> （角色 HP、连击伤害、必杀消耗、弹药、食物回复、敌人 HP 分层、
> 掉落表、关卡尺寸、时间限制），全部汇总在
> [08-rom-data-tables.md](./08-rom-data-tables.md)。
>
> 因此本页只在**仍然缺数据的地方**使用 `[推定]` 值，其余直接引用原版数值。

## 一、仍然缺失的数据怎么补

**已经不需要猜的部分**（直接用原版值）：角色 HP 与伤害、必杀消耗与无敌帧、
武器弹药、食物回复量、敌人 HP 分层、掉落概率、关卡尺寸与时间限制。

**仍然缺失的部分**（需要实测）：

| 缺失项 | 建议的补法 |
| --- | --- |
| 各动作的帧数（起手 / 判定 / 收招） | 从 ROM 动画表 `0xD6B28` 提取，或用 MAME 逐帧步进 |
| 移动速度 / 跳跃高度 / 攻击距离（像素） | MAME 读角色 X/Y 坐标（`+0x08` / `+0x10`）逐帧算 |
| 各敌人的 HP 与攻击伤害 | MAME 读 `$FFD364` 起的内存区 |
| 各 Boss 的 HP 与攻击循环 | MAME 读 `$FFDCA0` 等地址 |
| 输入窗口（连击取消、搓招容差） | 只能实测，或查 GameFAQs FAQ（目前不可访问） |

### 无数据时的通用方法

如果某个数值实在拿不到，用**以「普通攻击命中次数」为锚点**的方式反推：

1. 看原版录像，数出「用某角色普通连击打死某敌人需要多少下」。
2. 设 `普通攻击伤害 = 1 单位`，则敌人 HP = 需要的命中次数。
3. 其他攻击按比例换算（冲刺攻击 1.5~2、飞踢 1~1.5、必杀 3~5 单位）。

**实测工具**：把 DIP 开关 **B6 与 B8** 打开，游戏会**显示命中盒** ——
这是测判定范围最直接的手段。

| 必杀技伤害 | **20** | **20** | **20** | **23** |
| 必杀技自身消耗 | **14**（10 + 4） | 同 | 同 | 同 |

### 必须实现的「力量（Power）」系统

> ⚠️ **这是最容易漏掉的机制。** 原版伤害不是常数，
> 而是**随角色挨打而上升的力量值**缩放。

| 项目 | 值 |
| --- | --- |
| 力量表 | ROM `0x2C9B6`，共 128 字节 |
| 基准值 / 最大值 | **32** / **64**（伤害最高翻倍） |
| 当前值 | 角色存档槽 `+0xC6` |
| 变化条件 | **每次被击中重掷；残血更容易掷出高值，不受伤则保持** |

**基于力量表可以反推出伤害公式：**

```
最终伤害 = 基础伤害 × (当前力量 / 32)
```

验证：Jack 在力量 = 32 时连击伤害是 68，而 68 = 2 × 34，
说明这个「基础伤害」是写死在招式表里的固定值，力量只作为倍率。

> 复刻时至少要实现：**被击中 → 重掷力量（按已损失 HP 加权，见 08 §2）→ 伤害变化**。
> 不做这个机制，高难度下玩家会觉得明显打不动 Boss（而原版不会）。

### 位移相关数值（仍需实测）

| 属性 | 状态 |
| --- | --- |
| 移动速度 / 奔跑速度 | `[待核对]` —— ROM 中有表，但未在任何可达资料中列出 |
| 跳跃高度与滞空帧数 | `[待核对]` |
| 攻击距离（各角色） | 已知 **Mustapha 攻击距离明显更长**（原版 hack 日志中提到 "Mustapha with his big range"），但没有具体像素值 |
| Hannah 投掷距离倍率 | 定性已知「更高更远」，**具体倍率 `[待核对]`** |

建议这些值先在 Godot 里调到「手感接近」，再逐帧对比录像微调。

## 三、动作帧数

原版是 **59.6 Hz** 的 CPS-1 计时，且**引擎内部全部以「帧」计数**
（原版代码里的无敌时间、眩晕保护都是明确的帧数）。
复刻直接用 Godot 默认的 **60 Hz 物理帧**，1 帧 = 1 个物理帧即可。

### 原版已知帧数（`[MOD引原版]`）

| 项目 | 帧数 |
| --- | --- |
| 必杀技命中后的无敌 | **60 帧**（约 1 秒） |
| 敌人被击倒后的**眩晕免疫窗口** | **60 帧**（约 1 秒） |
| Boss 被击倒后的无敌 | **原版为 0 帧**（可无限连击锁定） |

| 普通攻击 2 | 5 | 4 | 10 | |
| 普通攻击 3（终结） | 8 | 5 | 16 | 带击退 |
| 抓取连打每一段 | 4 | 3 | 8 | 段数因角色而异（3 段） |
| 冲刺攻击 | 4 | 8 | 14 | **击倒** |

### 输入缓冲

| 输入 | 建议窗口 | 说明 |
| --- | --- | --- |
| 双击同方向 → 奔跑 | 12 帧（200 ms） | `[推定]` |
| `↓ ↑` 搓招 | 12 帧 | 依次输入，窗口太短会很难出招 |

## 四、Godot 实现要点

### 深度排序（清版动作游戏的核心）

- 使用 `Node2D.y_sort_enabled`（Godot 4 的 Y 排序）按 **Y 坐标**排序，
  让角色在前后移动时正确遮挡。注意 Y 排序的基准点应取**角色脚下**。
- 背景层与特效层用渲染层隔离：见
  [README 的物理层 / 渲染层](../README.md#物理层) 说明。

### 攻击判定

不要用「碰撞体互相撞」来实现攻击，建议：

1. 每个攻击动作用一组 **Hitbox（Area2D）**，通过 AnimationPlayer 的
   方法调用轨道在判定帧**打开 / 关闭**。
2. 每次挥击赋予一个自增的 `hit_id`，Hitbox 记录已命中的目标集合，
   **同一次挥击对同一目标只结算一次**（防止多帧重复伤害）。
3. 判定层对应关系：

   | 攻击方 | Hitbox 所在层 | 需要检测的层 |
   | --- | --- | --- |
   | 玩家攻击 | `player_attack` (3) | `enemy` (2)、`obstacle` (6)、`pickable` (5) |
   | 敌人攻击 | `enemy_attack` (4) | `player` (1)、`obstacle` (6) |

4. **受击盒（Hurtbox）** 放在各角色身上，位于 `player` / `enemy` 层。

### 状态机

每名角色一个有限状态机，状态至少包括：
`IDLE / WALK / RUN / ATTACK / JUMP / JUMP_ATTACK / GRAB / GRABBED / THROW / HIT / DOWN / RISE / SPECIAL / ITEM / DRIVE / CUTSCENE`

- 建议把「能否被抓」「能否被击倒」做成**角色数据里的开关**，
  而不是写在状态机里判断类型。
- `DRIVE` 状态专供第 3、4 关的 Cadillac 使用（切换操作目标为载具）。

### 数据表

建议把所有数值放进 Godot `Resource`（或 CSV / JSON），不要硬编码：

```
res://script/data/character_stats.gd      # 4 名角色的属性与倍率
res://script/data/move_data.gd            # 招式帧数、伤害、判定盒尺寸
res://script/data/enemy_stats.gd          # 敌人 HP、伤害、可抓取性
res://script/data/weapon_data.gd          # 武器伤害、弹数、掉落权重
res://script/data/stage_data.gd           # 每关的时间、敌人波次、掉落表
```

字段建议：

| 数据表 | 关键字段 |
| --- | --- |
| 角色 | `id`、`max_hp`、`speed`、`attack_power`、`weapon_power`、`throw_power`、`special_cost` |
| 招式 | `id`、`character`、`input`、`startup`、`active`、`recovery`、`damage`、`knockdown`、`hitbox_rect`、`invincible_frames` |
| 敌人 | `id`、`hp`、`damage`、`can_grab`、`can_knockdown`、`ai_profile`、`score_value`、`drop_table` |
| 武器 | `id`、类型、`damage`、`ammo`、`range`、`throwable`、`behavior_when_empty` |
| 关卡 | `stage_id`、`time_limit`、`waves[]`、`player_count_multiplier`、`areas[]` |
| 关卡区域（`areas[]` 的元素） | `size`、`walk_band(y_min, y_max)`、`vertical_scroll`、`camera_bounds`、`lock_triggers[]` |

### 人数联动的敌人生成

原版的刷怪记录（16 字节）里有一位 **「人数标记」**：
**0 = 总是生成，4 = 2 人时生成，6 = 3 人时生成**。
所以「人数越多敌人越多」是**数据驱动的，不是额外难度逻辑**。
复刻时只要在读取刷怪记录时按当前人数过滤即可。记录结构见
[05-stages.md](./05-stages.md#刷怪记录结构16-字节)。

同样地，第 7 关 Slisaur 的数量（单人 2 只 / 多人 3 只）应该写在关卡数据里。

### 同屏敌人槽位预算

原版对同时存在的敌人有**槽位预算**，不同敌人占用不同数量的槽位
（杂兵 1、Bludge 与雷龙腿 2、持刀近战与 Lash T. 3）。
不做这个限制会导致同屏敌人远多于原版。详见
[06-enemies-and-bosses.md](./06-enemies-and-bosses.md#生成槽位预算)。

## 五、原版机制实现清单（容易漏）

按「漏了会明显不对」的程度排序：

| # | 机制 | 为什么不能漏 |
| --- | --- | --- |
| 1 | **力量（Power）随挨打上升，缩放伤害** | 漏了高难度会明显打不动，手感与原版差别很大 |
| 2 | **敌人被击倒后 60 帧眩晕免疫** | 漏了会导致必杀技可以无限连晕 |
| 3 | **Boss 被击倒后没有无敌帧** | 原版可无限连击锁定 Boss；加不加是**设计选择**，但要知情 |
| 4 | **必杀技是两个独立 hitbox / 两段伤害** | 原版是第 1 段扣 10 HP、第 2 段扣 4 HP |
| 5 | **食物回复是固定 6 档**（100/80/64/48/32/16） | 不做表而逐个调参是浪费时间 |
| 6 | **血量以 100 为 1 格渲染** | 玩家血条 1 格 = 100 HP；敌人血条格数 = HP >> 2 |
| 7 | **对讲机 → Cadillac 的触发条件** | 原版只能在摄像机位置 `0x7D00` 之前呼叫、`0x3000` 之后才能下车 |
| 8 | **纵向卷轴不止第 7 关** | 第 7 关 B 段是 984×14320 的垂直下降；`cdree` 数据里**第 2 关 B（1624×512）与第 5 关（5528×480）也带 `verticalScroll` 标记**，第 1 关 A 段高 300 同样超出一屏。凡分段高度 > 224 都要做纵向夹取 |
| 9 | **恐龙是中立单位** | 第 2 关 T-Rex、第 6 关雷龙腿都应该**同时伤害玩家和敌人** |
| 10 | **换色复用** | Walther = Vice 换色、Slisaur = Slice 换色，都是调色板索引切换 |
| 11 | **边界靠夹取，不靠墙物件** | 摄像机夹取 + 玩家 X 夹在视野内 + 每区域可行走 Y 带 + 锁屏；少数实体（第 6 关恐龙脚）带 `noLevelLimits` 豁免 |

### 换色与调色板

原版有 16 个具名调色板（红 / 黄 / 紫 / 绿 / 蓝 / 米 / 粉 / 浅蓝 / 青 / 银 /
黑 / 赭 / 橙 / 绯 / 翠 / 蓝紫），**既用于玩家的选人换色，也用于敌人换色**。
复刻时用 Godot 的 `ShaderMaterial` 做调色板替换（index 查找）即可，
不需要为每个配色画一套图。完整调色板表见
[08-rom-data-tables.md](./08-rom-data-tables.md#调色板-16-色原版用作玩家的换色选人)。

### 掉落表实现

掉落表的分母固定为 **32**，直接实现为：

```gdscript
const DROP_TABLE_SIZE := 32

func roll_drop(table: Array[String]) -> String:
    assert(table.size() == DROP_TABLE_SIZE)
    return table[randi() % DROP_TABLE_SIZE]
```

不需要浮点权重，也不需要累计概率，很快且与原版一致。
（原版掉落 ID `10`~`13` 会崩溃，**不要复现**。）

## 六、多人、摄像机与全局流程

### 同屏多人与输入

- 输入映射已按 `p1_*` / `p2_*` / `p3_*` 前缀拆开（见
  [README 操作映射](../README.md#操作映射)），每个玩家对象只读自己前缀的动作。
- 建议写一个 `InputRouter` 单例，把「第 N 位玩家」抽象成
  `get_move_vector(player_index)`、`is_attack_just_pressed(player_index)`，
  这样单人测试和 3 人测试用同一套代码，且将来接手柄分设备时只改一处。
- 挂机检测 / 中途加入（drop-in）原版支持，复刻时按需实现。

### 摄像机与关卡分段

- 使用 `Camera2D` 跟随最靠前的玩家，并做**关卡边界夹取**：
  `limit_left = 0`、`limit_right = 区域宽度`、纵向段再夹 `limit_top/bottom`。
  原版视野常量 **384×224**，摄像机 X 实际活动范围是 `[0, 宽度 − 384]`。
- **玩家不能跑出地图靠四层机制**（依据见
  [05 §玩家为什么跑不出地图](./05-stages.md#玩家为什么跑不出地图边界与锁屏机制)）：
  1. 关卡尺寸夹取摄像机；
  2. 玩家 X 每帧夹在**当前视野矩形**内（左右各留边距，原版具体值 `[待核对]`）；
  3. 玩家 / 敌人 Y 夹在**该区域的可行走 Y 带**内
     （第 1 关：A 147/100、B 79/16、C 63/16）；
  4. `lock` 段期间摄像机冻结，视野右缘就是墙，
     直到「已生成敌人数」计数（原版 `$FFB358`）满足条件才解锁。
- 建议把每个区域做成一个 `AreaData` 资源：
  `size`、`walk_band(y_min, y_max)`、`vertical_scroll: bool`、`lock_triggers[]`；
  移动代码统一走 `clamp_to_area()`，玩家与敌人共用，
  只对少数「从画面外进来」的实体（原版第 6 关恐龙脚，`noLevelLimits`）跳过夹取。
- 关卡分为若干「战斗段」，每段用 `trigger` (7) 层上的区域标记：
  玩家进入 → **锁住摄像机** → 生成波次 → 全部清除 → 解锁并允许继续前进。
- 时间限制用一个 `Timer`，超时即扣命（原版行为 `[待核对]`）。

### 全局流程

需要一个顶层的游戏流程管理器，覆盖：
`开机演示（Attract） → 投币 → 选人 → 关卡 → 续关界面 → 通关结局 → 排行榜`

- 续关界面需要在 **20 秒**倒计时结束时播放「角色被射杀」演出，
  续关成功则播放「反击打倒对方」的演出，并**允许更换角色 + 发放 4 发火箭筒**
  （见 [03-controls-and-system.md](./03-controls-and-system.md#续关-continue)）。
- 段内**演出事件**（开场自动必杀、自动跳窗、Old Man 被杀、Fessenden 屏幕现身等）
  直接复用刷怪系统的「剧情专用对象 + AI 姿态 + 触发区间」实现，
  演出期间玩家进入 `CUTSCENE` 状态交出控制权；关卡间对话过场用自制
  `CutscenePlayer` 时间轴脚本 —— 详见

## 七、建议的实现顺序

1. 单角色（Jack）+ 一个空场景：移动、Y 排序、摄像机跟随。
2. 普通连击 + 受击 + 倒地 / 起身。
3. **力量（Power）系统** —— 越早加越好，它影响所有伤害计算。
4. 抓取 / 投技 / 抓取连打。
5. 冲刺、跳跃、飞踢、追踪踢、下上攻击。
6. 必杀技（两段伤害 + 自身扣 14 HP + 60 帧无敌）。
7. 武器拾取 / 投掷 / 枪械 + 掉落表。
8. 敌人 AI、刷怪波次（含人数标记与槽位预算）、关卡分段。
9. 其余 3 名角色（同一套逻辑 + 不同数据）。
10. Boss（先做 Vice，验证 AI 状态机）。
11. 多人同屏、续关、计分、结局。
